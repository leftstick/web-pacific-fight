## 2.6 程序化像素美术方案（关键工程决策）

**不要指望生图模型产出逐帧一致的动画**。正确做法是"分部件组装 + 调色板置换"：

1. 每个角色由可复用部件绘制：`头冠 / 头部 / 双眼 / 躯干 / 胸口计时器 / 肩甲 /
   上臂 / 前臂 / 大腿 / 小腿 / 光刃`，每个部件是一组预生成的像素块（离屏 canvas）。
2. 6 个角色共享同一套骨架与动作帧，差异来自：调色板（≤24 色）、头冠形状、
   计时器形状、胸甲纹样、体型系数（身高 100–116%、肩宽 90–115%）、光效颜色。
3. 动作帧由代码按姿态参数绘制（关节角度表），而不是逐帧手绘 —— 这样
   6 角色 × 40 帧不需要 240 张图，只需 40 组姿态参数 + 6 套外观参数。
4. 怪兽不做骨架复用，每只独立用 8–12 个部件拼装（体型更大 140–200px）。
5. 所有绘制结果缓存到离屏 canvas，按「角色 + 动作 + 帧」键索引，避免每帧重绘。

# 八、常见翻车点与修复提示词

| 现象 | 原因 | 修复提示词 |
|---|---|---|
| 手感"发飘"、打击没重量 | 缺 hitstop / 击退 / 震屏 | `给每招补命中停顿与受击抖动，重击加 6px 击退 + 2px 震屏，参考帧数据表` |
| 招式帧数和表对不上 | 用 deltaTime 直接推进动作 | `动作帧必须用逻辑帧计数推进，禁止用 deltaTime 驱动帧序号` |
| 判定框和画面不同步 | 判定框硬编码在绘制里 | `把 hitbox/hurtbox 全部移到 data 表，渲染时只读不写` |
| 6 个角色看起来像同一个 | 只做了调色板置换 | `除配色外必须改变头冠形状、计时器形状、胸甲纹样、肩宽比例` |
| 手机上一按按钮页面就滚 | 缺 touch-action 与 preventDefault | `html,body{overscroll-behavior:none;touch-action:none;user-select:none}` |
| 竖屏遮罩在 iOS 不消失 | 只监听 resize | `同时监听 orientationchange 与 visualViewport 的 resize` |
| 帧率掉到 30 | 每帧 new 对象 / 每帧重绘 sprite | `粒子与投射物用对象池；角色帧用离屏 canvas 缓存` |
| 连段伤害爆炸 | 没做伤害递减 | `连段伤害按 100/90/80/70/60% 递减，最低 30%` |
| 怪兽只是换皮 | 机制没落到 AI 与帧数据 | `每只怪兽的专属机制必须写进 ai.js 的状态机分支与帧数据` |

## 使用建议（给你的，不是给 AI 的）

1. **顺序不能乱**：P1 手感原型是整件事的成败点。P1 不通，后面全白做。
2. **每阶段都要求它给"可验证证据"**：帧数打印、gif、性能录制，别只看它说"已完成"。
3. 让 AI 先出文件树和导出签名，你审一遍再让它写实现，能省掉大量返工。
4. 想换美术风格时，只改 `render/pixel.js` 的调色板与部件参数，不要去动逻辑层。
