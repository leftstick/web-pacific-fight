# 《光之战士：像素对决》美术提示词合集
## 6 名原创「光之战士」+ 10 只原创怪兽

> 用途：生成**角色立绘 / 选人头像 / 宣传图 / 参考图**。
> **动作帧不要用生图模型做**——逐帧一致性必然崩，动作帧请交给代码按姿态参数绘制。
> 生图模型对英文提示词响应更稳，因此 prompt 主体用英文，中文只做说明。

## 零、通用规范（每条 prompt 都要带上）

### 0.1 风格锚定句（Style Anchor，固定不变）

```text
16-bit arcade pixel art, SNES-era fighting game sprite style, Street Fighter II aesthetic,
limited palette (24 colors max), 2px dark outline, hard edges, no anti-aliasing,
no gradients, no dithering blur, flat cel shading with 3 tones per color,
front-facing or 3/4 side view, full body visible from head to feet,
clean silhouette readable at 96px tall, transparent background
```

### 0.2 负面提示词（Negative，统一复用）

```text
photorealistic, 3d render, blurry, anti-aliased, smooth gradient, soft shadow,
realistic skin texture, anime cel shading with thick outline, watermark, text, logo,
signature, extra limbs, extra fingers, deformed hands, cropped head, cropped feet,
multiple characters, background scenery, busy background, drop shadow on floor,
JPEG artifacts, low contrast, washed out, oversaturated neon glow, lens flare
```

### 0.3 版权隔离句（每条必加，替换掉模型脑内的官方形象）

```text
original character design, not based on any existing copyrighted character,
original name and original costume patterns, generic tokusatsu hero archetype,
no recognizable franchise logo or insignia, no official chest emblem design
```

### 0.4 生成参数建议

| 项 | 建议值 |
|---|---|
| 出图尺寸 | 1024 × 1024（后期降采样到 256×256 或 128×128） |
| 采样步数 | 30–40 |
| CFG | 7–9（太高会硬化，太低会跑偏） |
| 固定 seed | 每个角色锁定一个 seed，方便微调时保持一致性 |
| 后期 | 最近邻降采样 → 品红底 #FF00FF 抠图 → 转 RGBA |
| 交付 | 每角色 3 张：正面站姿全身 / 半身头像 / 战斗姿态 |

### 0.5 sprite sheet 规范（如果你确实要试着生成立绘集）

```text
single horizontal sprite sheet, 8 columns x 4 rows grid, each cell 128x128 px,
evenly spaced, consistent character size across all cells,
row1: idle 4 frames + walk 4 frames
row2: punch 3 frames + kick 3 frames + hit reaction 2 frames
row3: jump 3 frames + crouch 3 frames + block 2 frames
row4: special move 6 frames + victory 2 frames
transparent background, no grid lines, no labels, no frame numbers
```

> 现实提醒：即使这样写，模型也很难保证 32 格动作连贯。**建议只取其中 2–4 格做参考，动作帧用代码重画。**

## 五、把生图结果变成可用素材（工程步骤）

1. 1024×1024 出图 → 最近邻（nearest neighbor）降到 128×128 或 256×256，
   否则像素不是"真像素"，放大后会糊。
2. 品红底（#FF00FF）出图的话，用色键抠图转 RGBA；如果没有品红底，用边缘 flood fill。
3. 统一调色板：把所有结果量化到同一套 32 色板（如 DB32 / AAP-64 子集），
   这样 6 角色摆在一起才不会花。
4. 检查 1px 网格：像素块必须是整数倍缩放（×2 / ×3 / ×4），
   否则 canvas 里会出现半像素抖动。
5. 放进 `assets/sprites/`，命名 `hero_nova_idle.png` 这样；
   代码检测到文件缺失就用程序化绘制回退。
